# TTS服务优化修复日志

## 问题描述
TTS服务在生成第4个音频片段时出现网络连接中断，导致整个批次失败。原因：
1. 每个角色发言过长（300字符），导致TTS处理时间过长
2. 网络超时设置不合理（90秒太长）
3. 单个片段失败会影响整个批次
4. 重试机制不够灵活

## 修复方案

### 1. 缩短角色发言长度 ✅
**文件：** `src/lib/prompt-manager.ts`
**修改：**
- 将所有角色的发言限制从300字符缩短到150字符
- 对应约20-25秒的语音播放时间
- 更新所有系统指令和阶段提示词

**影响：**
- 减少单次TTS处理时间
- 降低网络超时风险
- 提高语音质量和播放流畅性

### 2. 优化TTS客户端超时控制 ✅
**文件：** `src/lib/indexTTS-private-client.ts`
**修改：**
- 添加45秒请求超时（原来没有）
- 减少重试延迟从2000ms到1500ms
- 使用Promise.race实现超时控制

**影响：**
- 更快发现网络问题
- 避免长时间等待
- 提高整体响应速度

### 3. 增强批量处理错误处理 ✅
**文件：** `src/lib/indexTTS-integrated-service.ts`
**修改：**
- 为每个片段添加独立的重试机制（最多2次）
- 单个片段失败不影响其他片段
- 片段间延迟从1000ms减少到800ms
- 详细记录失败原因

**影响：**
- 提高批次完成率
- 更快的整体处理速度
- 更好的错误诊断

### 4. 缩短管道超时时间 ✅
**文件：** `src/lib/pipeline-orchestrator.ts`
**修改：**
- TTS任务超时从90秒减少到60秒
- 更符合实际处理时间需求

**影响：**
- 更快发现TTS服务问题
- 避免用户长时间等待
