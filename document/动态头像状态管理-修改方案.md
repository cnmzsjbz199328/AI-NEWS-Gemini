# AI TV 动态头像状态管理 - 完整修改方案
## 基于并行生成 + 串行播放架构

---

## � 核心设计理念

你强调的是：
- **文本生成返回值 B 一旦可用** →
  1. 可以立刻触发本角色的语音生成 API 调用（B → 语音 C）
  2. 同时也能把 B 作为上下文传递给下一角色的文本生成 API（B + A → D）

也就是说：
- **文本生成 → 语音生成** 和 **文本生成 → 下一角色文本生成** 是 **并行/异步** 的，完全不需要等待语音播放完成
- 但 **音频播放仍然严格按序号管理**

## 🎯 AI TV 发言与流程设计（并行生成 + 串行播放）

### 1. 输入来源
- 系统从 **新闻列表** 获取新闻片段（记为 A）

### 2. Speaker 1 流程
1. **获取内容**：输入 A
2. **调用文本生成 API（异步）**：输入 A → 返回文本 B
3. **文本 B 一旦返回** → 触发两个并行流程：
   - **语音生成**：B → 调用语音生成 API（异步）→ 得到语音 C → 标记序号 0 = 已准备
   - **传递上下文给下一角色**：B 与 A 一并传递给 Speaker 2 的文本生成 API
4. **播放控制**：
   - Audio Manager 检查序号为 0，说明是第一个，则播放 C（状态 = 正在播放）
   - **播放时**：展示 B，头像动态化
   - **播放完毕**：状态 = 已播放，头像恢复静态

### 3. Speaker 2 流程
1. **获取上下文**：输入 A + B
2. **调用文本生成 API（异步）**：输入 A + B → 返回文本 D
3. **文本 D 一旦返回** → 触发两个并行流程：
   - **语音生成**：D → 调用语音生成 API（异步）→ 得到语音 E → 标记序号 1 = 已准备
   - **传递上下文给下一角色**：D 与 A + B 一并传递给 Speaker 3 的文本生成 API
4. **播放控制**：
   - Audio Manager 检查序号 0 是否已播放 → 若已完成，则播放 E
   - **播放时**：展示 D，头像动态化
   - **播放完毕**：状态 = 已播放，头像恢复静态

### 4. Speaker 3 流程
1. **获取上下文**：输入 A + B + D
2. **调用文本生成 API（异步）**：输入 A + B + D → 返回文本 F
3. **文本 F 一旦返回** → 触发两个并行流程：
   - **语音生成**：F → 调用语音生成 API（异步）→ 得到语音 G → 标记序号 2 = 已准备
   - **传递上下文给下一角色**（若有）
4. **播放控制**：
   - Audio Manager 检查序号 1 是否已播放 → 若已完成，则播放 G
   - **播放时**：展示 F，头像动态化
   - **播放完毕**：状态 = 已播放，头像恢复静态

### 5. 全局控制（Audio Manager）
- **职责**：保证音频播放严格顺序化
- **规则**：
  - 每个语音生成完成时 → 状态 = 已准备
  - 只有当「前一个序号 = 已播放」时，当前语音才能开始播放
  - **播放时** → 同步展示文本 + 动态头像
  - **播放结束** → 标记为已播放

### 6. 异步与并行特性
1. **文本生成 API 调用是异步的**，完成后即触发：
   - 本角色语音生成
   - 下一角色文本生成
2. **语音生成 API 调用是异步的**，生成结果进入「已准备」，等待 Audio Manager 播放
3. **音频播放严格串行**（受序号控制），不会并行重叠
4. **文本展示与语音播放严格绑定**：文本只在语音开始播放时展示

**整体效果**：
- **生成是并行的**（文本/语音可以同时生成，跨角色文本生成也能立刻启动）
- **播放是串行的**（由 Audio Manager 管理顺序）
- **展示与播放严格同步**

### 3. 关键时序控制

#### 3.1 文本生成完成后的并行触发
```typescript
async function onTextGenerated(speaker: Speaker, text: string, context: string[]) {
  const sequenceNumber = getNextSequenceNumber()
  
  // 并行启动两个流程
  Promise.all([
    // 1. 语音生成（异步）
    generationManager.generateAudio(speaker, text, sequenceNumber),
    
    // 2. 下一角色文本生成（异步）
    generationManager.triggerNextSpeaker(speaker, text, context)
  ])
  
  // 更新UI显示文本（立即）
  updateConversationDisplay(speaker, text)
}
```

#### 3.2 语音播放与动画同步
```typescript
class AudioManager {
  async playAudio(audioItem: AudioItem) {
    // 开始播放前：设置动画状态
    speakerStateManager.setSpeaking(audioItem.speaker)
    
    // 播放语音
    const audio = new Audio(URL.createObjectURL(audioItem.audioBlob))
    
    audio.onended = () => {
      // 播放完成：恢复静态状态
      speakerStateManager.setStatic(audioItem.speaker)
      this.onAudioComplete(audioItem.sequenceNumber)
      this.tryPlayNext() // 尝试播放下一个
    }
    
    await audio.play()
  }
}
```

### 6. 关键技术难点

#### 6.1 并行控制
- **挑战**：确保文本生成完成后正确触发两个并行流程
- **解决方案**：使用 Promise.all 管理并行任务，独立错误处理

#### 6.2 序号管理
- **挑战**：保证音频严格按顺序播放
- **解决方案**：使用递增序号，Map存储，状态机控制

#### 6.3 状态同步
- **挑战**：多个管理器间的状态一致性
- **解决方案**：中心化状态管理，回调机制，单向数据流

#### 6.4 资源管理
- **挑战**：音频Blob内存使用，定时器清理
- **解决方案**：及时释放资源，useEffect清理机制
